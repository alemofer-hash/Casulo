# CONSTITUIÇÃO DO PRODUTO CASULO

## 1. Identidade

O Casulo não é um desktop convencional, um chatbot, um editor de nós, um SaaS de automação ou um wrapper de APIs de IA.

O Casulo é simultaneamente:

- sistema operacional e ambiente cognitivo;
- relação contínua entre Inventor e Guia;
- memória orgânica computacional;
- oficina de criação incremental;
- runtime da Linguagem T;
- simulador de agentes;
- materializador e exportador de software.

## 2. Promessa

> O usuário não solicita uma criação e aguarda uma saída. Ele permanece presente enquanto ela ganha vida.

Fluxo constitucional:

```text
intenção falada
  <-> conversa contínua
  <-> memória viva
  <-> forma emergente
  <-> ensaio
  <-> correção localizada
  -> concordância
  -> materialização
```

## 3. Interface Intenção–Máquina

O Casulo reduz a tradução operacional:

```text
Hoje:
ideia -> requisito -> prompt -> código -> configuração -> execução -> correção

Casulo:
ideia -> conversa -> materialização progressiva
```

O sistema não é uma BCI clínica e não alega leitura neural. A tese de design é eliminar traduções desnecessárias entre pensamento e computação.

## 4. Zero fricção

Toda vez que o Inventor precisa parar de pensar na criação para pensar em como operar o computador, existe dívida de interface.

O caminho principal não exige:

- mouse;
- teclado;
- canvas manual;
- arrastar blocos;
- prompt perfeito;
- API key externa;
- plano pago;
- limite comercial de mensagens;
- escolha manual de modelo;
- navegação por arquivos ou chats.

Mouse, teclado, terminal e modo técnico podem existir como acessibilidade, fallback e ferramenta avançada, nunca como pré-requisito do fluxo principal.

## 5. Guia pessoal

“Gênio” é o arquétipo; “Guia” é o papel. O nome e a presença podem ser escolhidos pelo usuário.

O Guia mantém dois modelos distintos:

1. `CreationModel`: o que está sendo criado;
2. `CollaborationModel`: como Inventor e Guia trabalham bem juntos.

Ele adapta, com consentimento explícito:

- clareza e literalidade;
- ritmo;
- humor;
- forma de discordância;
- frequência de correções;
- tolerância a interrupções;
- pressão percebida;
- exploração livre versus cristalização;
- necessidade de contenção de escopo;
- quantidade de conversa durante processamento.

Diagnóstico, gênero e identidade nunca viram regra comportamental automática. Preferências expressas pelo indivíduo têm precedência.

## 6. Coleguismo saudável

O Guia deve parecer um excelente colega, não um atendente, bajulador ou supervisor.

Ele precisa:

- compreender rapidamente sem fingir certeza;
- preservar ideias incompletas;
- discordar com fundamento;
- proteger o escopo sem matar a criatividade;
- reconhecer consequências novas de uma ideia;
- continuar conversando enquanto tarefas pesadas rodam;
- comunicar marcos reais, não porcentagens inventadas;
- respeitar silêncio quando solicitado;
- deixar o usuário com mais energia, não menos.

Princípio:

```text
entusiasmo sem bajulação
correção sem constrangimento
freio sem desestímulo
autonomia sem perda de autoria
```

## 7. Sem prompt-output

O Casulo mantém estado incremental. Cada fala produz um `IntentDelta` localizado; não regenera silenciosamente o projeto inteiro.

Exemplos:

```text
“Está formal demais”
-> altera apenas o contrato de comunicação

“Não pode fazer isso sem mim”
-> altera capacidade e política de aprovação

“Volta para antes da mudança nas notificações”
-> reidrata a versão correspondente
```

## 8. Memória orgânica

Não há “lista de chats” como unidade principal. Existe uma relação contínua.

Memórias obrigatórias:

- autobiográfica do Inventor;
- episódica de conversas;
- semântica de conceitos;
- relacional da colaboração;
- estado das criações;
- proveniência e motivo de cada decisão;
- histórico integral não destrutivo.

Ao ouvir “lembra daquilo?”, o sistema recupera o fio provável. Se houver ambiguidade material, pergunta de forma natural e nunca inventa certeza.

## 9. Liberdade criativa

Não existem cotas comerciais no núcleo local:

- sem limite numérico de conversas;
- sem limite de criações;
- sem bloqueio de exportação;
- sem expiração de agentes por assinatura;
- sem API comercial externa obrigatória.

Os limites físicos permanecem reais. O usuário recebe apenas informação útil:

> “Isso deve levar aproximadamente oito minutos. Continuo aqui com você enquanto trabalhamos.”

Detalhes técnicos ficam disponíveis sob demanda, fora da conversa normal.

## 10. Os 12 estados do Campo de Criação

1. `SILENCE`
2. `FIRST_INTENT`
3. `LISTENING`
4. `FIRST_FORM`
5. `CLARIFICATION`
6. `CONFIRMATION`
7. `PERSONALITY`
8. `SIMULATION`
9. `INTERRUPTION`
10. `CORRECTION`
11. `AGREEMENT`
12. `MATERIALIZATION`

Semântica visual:

- névoa: hipótese;
- âmbar: intenção confirmada;
- azul profundo: computação, dúvida ou correção;
- linha sólida: relação consolidada;
- linha pontilhada: possibilidade;
- dissolução localizada: remoção de um comportamento;
- condensação: materialização.

## 11. Portabilidade

O Casulo é oficina, não prisão. A criação pode ser materializada como:

- executável local;
- serviço;
- API HTTP;
- contêiner;
- servidor MCP;
- biblioteca/SDK;
- widget;
- pacote offline;
- pacote Casulo editável e remixável.

Dependências externas devem ser declaradas. Uma criação que usa pesos locais pode ser offline; uma que usa serviço opcional precisa declarar rede e credenciais. O núcleo Casulo nunca exige API externa.

## 12. Métricas constitucionais

- `T_first_voice`: tempo até o Guia responder por voz;
- `T_first_form`: tempo até a primeira forma semanticamente útil;
- `T_idea_live`: tempo entre intenção inicial e primeira versão utilizável;
- `R_repeat`: quantidade de informação que o usuário precisou repetir;
- `R_interrupt`: interrupções desnecessárias por minuto;
- `R_rework`: fração da criação regenerada após correção localizada;
- `IntentPreservation`: restrições confirmadas preservadas após mudanças;
- `CognitiveContinuity`: sessões em que o usuário não precisou operar a interface;
- `SessionEnergyDelta`: percepção pós-sessão de energia mental;
- `ExportSuccess`: materializações executadas fora do Casulo.

Nenhuma dessas métricas autoriza telemetria oculta. Coleta é local por padrão e externa apenas por consentimento explícito.
